converter — читает данные из файла или стандартного ввода, конвертирует между форматами, выводит результат.
comparer — читает два файла, парсит их через библиотеку и сравнивает списки транзакций.
     

## Спецификация бинарного формата (.bin)

Бинарный формат разработан для эффективного хранения и быстрого парсинга записей `AppData` без использования сторонних библиотек сериализации. Файл имеет строгую зеркальную структуру, состоящую из заголовка и последовательности блоков данных.

Все числовые значения (длины полей, суммы, счетчики) записываются в формате **Little-Endian**.

### Структура файла

Файл состоит из двух основных частей: **Заголовок (Header)** и **Данные (Payload)**.

#### 1. Заголовок файла (Занимает первые 8 байт)
* **Сигнатура формата (Идентификатор):** `4 байта`. Всегда содержит ASCII-символы `BINF` (байты `[0x42, 0x49, 0x4E, 0x46]`). Используется для валидации типа файла при чтении.
* **Количество записей:** `4 байта` (`u32`). Хранит общее число объектов данных, записанных в файле. Позволяет парсеру точно знать границы циклов чтения.

#### 2. Структура одной записи данных (Payload)
Каждая запись считывается последовательно и состоит из следующих полей:

| Имя поля | Тип данных | Размер | Описание |
| :--- | :--- | :--- | :--- |
| **Длина даты** | `u32` | 4 байта | Количество байт, которое занимает строка `date` |
| **Дата** | Строка UTF-8 | Динамический | Сырые байты текста даты (длина указана шагом ранее) |
| **Длина категории** | `u32` | 4 байта | Количество байт, которое занимает строка `category` |
| **Категория** | Строка UTF-8 | Динамический | Сырые байты текста категории |
| **Длина типа операции**| `u32` | 4 байта | Количество байт, которое занимает строка `operation_type` |
| **Тип операции** | Строка UTF-8 | Динамический | Сырые байты текста типа операции |
| **Сумма** | `u32` | 4 байта | Числовое значение финансовой суммы операции `summ` |

---

### Безопасность и обработка ошибок

Парсер встроен в библиотеку и гарантирует защиту от повреждения данных:
1. **Проверка подписи:** Если первыми четырьмя байтами файла не являются `BINF`, библиотека мгновенно прекращает чтение и возвращает ошибку `InternalErrors::InvalidInput`, предотвращая переполнение памяти.
2. **Валидация UTF-8:** Каждое строковое поле проверяется на соответствие стандарту UTF-8. Наличие битых байт вызывает безопасный возврат ошибки, исключая аварийное завершение (`panic!`) программы.


## Руководство по использованию CLI-приложения

Приложение поддерживает три режима работы: запись из стандартного ввода (`write`), чтение и вывод на экран (`read`), а также взаимную конвертацию файлов (`convert`).

### Доступные форматы данных
* `text` — текстовые строки без заголовка, разделитель — точка с запятой `;` (Пример: `2026-10-04;Продукты;Расход;1500`).
* `csv` — стандартный CSV-формат с обязательной строкой заголовка `name,version...` на первой строчке и разделителем-запятой `,`.
* `binary` (или `bin`) — защищенный кастомный бинарный формат с заголовком `BINF` и метаданными.

---

### 1. Запись данных (`write`)

Режим `write` использует концепцию **потокового ввода (Unix-way)**. Приложение считывает данные из стандартного ввода (`stdin`) в многострочном формате до тех пор, пока не встретит маркер конца файла (**`EOF`**). 

#### Интерактивный ввод руками:
Запустите команду, вставьте данные построчно, а затем нажмите **`Ctrl+D`** (в Linux/macOS) или **`Ctrl+Z` + `Enter`** (в Windows):

```bash
# Для текстового формата:
cargo run -- write text output.txt
# [Вставьте строки ниже]
2026-04-01;salary;income;120000
2026-04-02;rent;expense;40000
# [Нажмите Ctrl+D / Ctrl+Z]

# Для CSV формата (заголовок вводить обязательно!):
cargo run -- write csv output.csv
# [Вставьте строки ниже]
date,category,kind,amount
2026-04-01,salary,income,120000
2026-04-02,rent,expense,40000

# [Нажмите Ctrl+D / Ctrl+Z]
```

cargo run -- write binary output.bin
# [Вводим строки]
2026-10-04;Продукты;Расход;1500

#### Потоковая передача через конвейер (Pipes):
Вы можете перенаправлять данные напрямую из других файлов или утилит без ручного ввода:
```bash
# Передача содержимого готового текстового файла в CSV:
cargo run -- write csv clean_data.csv < raw_dump.csv

# Передача через пайп (cat):
cat my_transactions.txt | cargo run -- write text saved_log.txt
```

---

### 2. Чтение данных (`read`)

Считывает указанный файл средствами библиотеки, валидирует структуру, заголовки и выводит распарсенный массив объектов в удобочитаемом виде (`Debug` форматирование).

```bash
# Чтение текстового лога:
cargo run -- read text saved_log.txt

# Чтение таблицы CSV (заголовок автоматически пропустится парсером):
cargo run -- read csv clean_data.csv

# Чтение бинарного файла (автоматически проверится сигнатура BINF):
cargo run -- read binary test.bin
```

---

### 3. Конвертация между форматами (`convert`)

Благодаря единому промежуточному представлению данных внутри библиотеки, вы можете свободно конвертировать файлы между любыми поддерживаемыми форматами в любых направлениях.

**Синтаксис:**
```bash
cargo run -- convert <из_формата> <входной_файл> <в_формат> <выходной_файл>
```

#### Примеры команд:
```bash
# Из CSV с запятыми в Бинарный файл (с автоматической генерацией BINF заголовка):
cargo run -- convert csv data.csv binary output.bin

# Из Бинарного файла обратно в обычный читаемый Текст с разделителем ";":
cargo run -- convert binary output.bin text report.txt

# Из Текста в CSV (библиотека сама добавит нужную строку заголовка на первую строчку):
cargo run -- convert text report.txt csv final_table.csv
```

#### Важная заметка для пользователей Windows (PowerShell vs MSYS2)

При работе с сырым бинарным форматом (`bin`/`binary`) стандартный терминал Windows **PowerShell** принудительно перекодирует поток `stdout` в текстовый формат (UTF-16), что **безвозвратно повреждает структуру бинарного файла** `BINF` (парсер выдаст ошибку `UnexpectedEof` или `failed to fill whole buffer`).

Для корректной потоковой конвертации и перенаправления байт в Windows используйте один из двух подходов:

1. **POSIX-окружение (Рекомендуется):** Запускайте команды внутри **MSYS2**, **Git Bash** или **WSL**. Там потоки работают в честном бинарном режиме, а ввод завершается стандартной Unix-комбинацией **`Ctrl+D`**:
   ```bash
   cargo run -- convert csv bin > data/result.bin
   ```

2. **Явные файлы в аргументах:** Если вы используете обычный PowerShell, избегайте перенаправления `>` и передавайте пути к файлам напрямую в аргументы утилиты — в этом режиме байты пишутся на диск в обход кодировок терминала:
   ```powershell
   cargo run -- convert csv data/sample.csv bin data/result.bin
   ```

---
### 4. Сравнение данных (`comparer`)

Дополнительная независимая утилита `comparer` позволяет построчно сопоставлять транзакции из двух любых источников. Логика полностью абстрагирована, что даёт возможность сравнивать файлы как в одинаковых, так и в совершенно разных форматах (например, сырой CSV с бинарным бэкапом).

Утилита проверяет:
1. Совпадение общего количества транзакций.
2. Построчное равенство всех полей (`date`, `category`, `operation_type`, `summ`).

#### Синтаксис и примеры команд

Интерфейс командной строки автоматически подстраивается под количество аргументов:

**Сценарий А: У файлов одинаковый формат** (Формат указывается 1 раз):
```bash
cargo run --bin comparer -- <формат> <путь_к_файлу1> <путь_к_файлу2>

# Пример: Сравнение двух CSV таблиц
cargo run --bin comparer -- csv data_october.csv backup_october.csv
```

**Сценарий Б: У файлов разные форматы** (Явно указываются оба формата):
```bash
cargo run --bin comparer -- <формат1> <путь_к_файлу1> <формат2> <путь_к_файлу2>

# Пример: Проверка бинарного файла на соответствие исходному текстовому логу
cargo run --bin comparer -- binary backup.bin text transactions.txt
```

####  Результаты работы и лимиты
* **При полном совпадении** утилита выведет:  
  `Успех: Файлы абсолютно идентичны!` и завершится с кодом `0`.
* **При больших объемах данных** утилита защищает терминал от бесконечного спама. Встроенный лимит останавливает сбор расхождений после первых **5 найденных ошибок**.
* **Пример вывода при расхождениях** (утилита завершится с ошибкой `1`):
  ```text
  Транзакции отличаются на позиции 3:
    amount: 6500 != 7000
  Транзакции отличаются на позиции 12:
    category: 'Продукты' != 'Транспорт'
    amount: 1200 != 450
  ... Достигнут лимит вывода ошибок (выведено 5) ...
  ```

#### Заметка для пользователей Windows (PowerShell)
В среде Windows PowerShell стандартное перенаправление через `<` не поддерживается. Вместо этого используйте передачу через пайплайн (`|`):
```powershell
Get-Content data/sample.txt | cargo run -- write binary data/stream_out.bin
```
